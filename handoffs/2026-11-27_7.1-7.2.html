3.3 Algorithm (suggested; keep it short and readable)

  1. STOP: the whole normalised message is in STOP_WORDS → intent STOP, tool stop, args {}.
  2. Span finding: tokenise norm(text). Slide n-grams longest first (4 → 1 tokens). Mark a span as crop or place when resolve_* returns anything except UNKNOWN on an exact alias. Try fuzzy only on leftover tokens of length ≥ 4, so short words like "khan" or "do" don't match. Tokens already used cannot be reused. Two crop spans → crop list (T-AMB-06). A "<word> mandi" with no resolved place → place UNKNOWN with raw = that word (T-AMB-03 "Block").
  3. Quantity: find a unit token (mann, maund, kg, ton, bori…) or a number directly before a crop. Pass the span number + unit to quantity(). raw must be the exact substring of the input (the test checks raw in input). Watch out: Punjabi "ton" can mean "from", as in voice item V21 "Kasur ton…".
  4. Intent (first match wins): STOP → ALERT (above/below/upar/neeche + number, "bata dena", "tell me when") → WHERE_TO_SELL ("kahan bech", "kis mandi", "best mandi", "where should I sell", "sell karna", "bhejun") → OUTLOOK (month horizon or "outlook") → FORECAST (future horizon or "forecast") → PRICE_NOW ("rate", "bhaao", "price", "qeemat") → HELP ("help", "madad", "kaise use") → OTHER.
  5. Outcome (SPEC §2.5):
    • Uncovered crop (kapas, chawal) → OUT_OF_COVERAGE. Place outside Punjab → OUT_OF_COVERAGE.
    • OTHER, or a non-price question → OUT_OF_SCOPE.
    • A required slot is missing → CLARIFY with the first missing in the order crop, place, quantity_unit, horizon. WHERE_TO_SELL needs crop + origin + quantity in kg; FORECAST needs h; AMBIGUOUS horizon → CLARIFY horizon.
    • WHEAT only with OUTLOOK.
  6. Tool (only when outcome = ANSWER) from the §2.5 table: price_now(crop, mandi), get_forecast(crop, mandi, h), best_mandis(crop, origin, quantity_kg), get_outlook(crop, month[, mandi]), set_alert(crop, mandi, direction, threshold), stop().
