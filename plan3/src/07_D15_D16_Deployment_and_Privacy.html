│   └─ adapters: WhatsAppGateway, LLM, STT, Storage   │

               ▼
        PostgreSQL (one DB: prices, forecasts, state, queue, logs)
        + a local disk folder for raw source files (hashed, backed up)
  • One VM, Docker Compose: caddy, web, worker, postgres, plus a cron/APScheduler entry for the batch role. No Kubernetes, no Redis, no message broker, no object store (we have no images; audio is transient).
  • Research and training run on laptops; the VM only scores with frozen model files committed with their ps_id.
  • Seams kept clean from Day 1 (cheap now, expensive later): every external service behind an adapter with keys from env; no secret in the repo (gitleaks in CI); the queue in Postgres; config per environment (dev / demo / user-test).
  • Backups: nightly pg_dump + raw folder sync to the private cloud folder (fetch policy rule 12).

  • Prompts: phone numbers never sent to the LLM; the user is "farmer".

4. D15: Hosting and deployment → DECIDED

  • One container image with web, worker and batch roles; Docker Compose on one free-tier VM with Caddy HTTPS; Postgres in a container with nightly dumps.
  • FYP-I: VM up by Day 2 (development may also use a tunnel); FYP-II: same VM unless credits expire, in which case move to Oracle Always-Free (a config change: everything is plain Docker + Postgres).

5. D16: Privacy, consent and retention → DECIDED

  • Consent on first contact; STOP deletes; numbers encrypted + hashed; 90-day message retention; audio deleted after transcription; no farmer data to free-tier vendors; no farmer data used to train or tune anything (Meta §4.7).
  • Single tenant: no multi-tenant row-level security (Manzil needed it for many agencies; MandiSaathi has one operator). This is a deliberate cut, recorded so nobody adds it "for later".
