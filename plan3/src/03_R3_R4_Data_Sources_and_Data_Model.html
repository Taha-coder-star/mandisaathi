2. D3 / D4: source and split decisions

D3 → Source-independent design, AMIS as the guaranteed source, Zarai Mandi as the preferred live source.

  • Every source has its own loader that writes the same canonical table (price_obs). Models never see source formats.
  • When both sources report the same mandi × crop × day, precedence for the live bot: Zarai Mandi, then AMIS; for research: AMIS, unless written permission to publish Zarai Mandi-based results exists. The reply always names the source of the number shown.
  • Fallback trigger: if no Zarai Mandi sample by Day 3 (Wed 25 Nov) or no export promised by Day 10 (Fri 4 Dec) → AMIS-only for FYP-I, recorded as a decision.

D4 → Splits fixed before any modelling.

  • Lockbox: AMIS data 2025-11-01 → 2026-10-31 (the final 12 months), stored in a separate sealed folder with its SHA-256 written in DECISIONS.md. Opened once, in FYP-II sprint S8.
  • Development: everything before 2025-11-01, used with rolling-origin folds (file 04).
  • Live period: from the bot's go-live onward. Live accuracy is reported separately and never mixed with lockbox results.
  • Published numbers (report, paper) use AMIS unless D3's permission condition is met.

4. Crop and place gazetteers (D5)

4.1 Normalisation before lookup (text and voice transcripts alike)

  1. Lowercase; strip punctuation; collapse spaces; Urdu-script tokens mapped to a Roman key (پیاز → pyaz, ٹماٹر → tamatar, آلو → aloo, گندم → gandum).
  2. Spelling canonicalisation: piaz, payaz, pyaaz → pyaz · timatar, tamater → tamatar · alu, aaloo → aloo · kanak (Punjabi) → gandum.
  3. Number words (shared with the quantity normaliser, §5): ek, do, teen … sau, hazaar, dedh, dhai, sawa, saade, paune.

4.3 Place resolution (same pattern as Manzil's location resolver)

  1. Exact alias hit on a mandi → RESOLVED (mandi).
  2. Exact alias hit on a city/district → RESOLVED (place) with its candidate mandis; F2 uses all of them, "price now" shows the main one and names it.
  3. Location pin → nearest district centroid; origin = the pin itself for distances. Pin outside the covered provinces → OUT_OF_COVERAGE.
  4. Fuzzy (trigram) on aliases: one candidate ≥ 0.85 with margin ≥ 0.15 → RESOLVED and echoed with the canonical name; otherwise AMBIGUOUS (ask with ≤ 3 buttons).
  5. A place in another province ("Hyderabad", "Peshawar") → OUT_OF_COVERAGE: "Abhi sirf Punjab ki mandiyon ka data hai."
  6. Nothing found → UNKNOWN: say so and list how to send a pin. The LLM never invents a place or a mandi ID.

  • Money display: "Rs 2,850–3,000 fi mann (40 kg)". Large sums: "≈ Rs 1,47,000" (South Asian grouping). Never another currency.
  • Number words: sau = 100, hazaar = 1,000, lakh = 100,000; dedh = 1.5, dhai = 2.5, sawa X = X + 0.25, saade X = X + 0.5, paune X = X − 0.25 (same table as Manzil D11, reused).
  • Dates: "aaj", "kal" (ambiguous: tomorrow or yesterday; future tense → tomorrow), "agle hafte" = days 1–7, month names in Urdu and English; all in PKT.

6. Quality rules

  • Outlier flag SUSPECT when the mid price moves more than 4 robust standard deviations from the series' 28-day median, or min > max, or the value is ≥ 5× its neighbours on the same day ASSUMPTION, tuned in the audit (E1).
  • SUSPECT rows are excluded from alerts and from "price now" until the next day confirms them; they stay in the table for audit.
  • A series is eligible for F1/F2 only if it has ≥ 60% of trading days in the last 12 months and a recent quote within 3 trading days (plan pack 2 rule, kept).

7. Frozen demo snapshot (for file 10 scenarios)

  • S-DEMO: a database dump of the synthetic dataset (A1, §9) taken after the generated load of Fri 11 Dec 2026 with forecast run R-20261211, frozen and tagged. The jury demo runs on it, so every expected answer can be computed in advance.
  • scripts/expected_answers.py computes the golden answer for each scenario from S-DEMO (latest rate, F1 range, F2 top-3 with net rupees, F3 outlook if available) and writes demo/golden/*.json. Success = the bot's reply facts equal the golden file.
  • Coverage required in S-DEMO: onion, tomato and potato, each with ≥ 5 eligible Punjab mandis including Lahore, Okara and Sahiwal; distances cached for origins Okara, Sahiwal, Kasur and Lahore.
  • A demo_reset.sh restores S-DEMO in under 2 minutes.

8. D5: Canonical data model and normalisation → DECIDED

  • One canonical price table in PKR per 100 kg, with raw value and unit kept; reported_at on every row enforces the timing rule.
  • Hand-curated crop and place gazetteers with Urdu-script, spelling, Punjabi and voice-STT aliases; the LLM picks only from resolver candidates.
  • Farmer-facing unit: per mann (40 kg). "Bori", "crate" and missing units are always asked about, never assumed.
  • The same normalisers serve the bot (text and voice) and the data loaders, so both sides speak the same units.
