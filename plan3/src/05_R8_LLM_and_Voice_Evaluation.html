4. Benchmark design (≈ 105 items + controls)

All items are written or recorded by the team and volunteers, never collected from farmer chats (Meta §4.7, file 02 R2). Gold data per item: input, gold transcript (voice, Roman and Urdu script), gold slots JSON, expected tool call and arguments, expected outcome (golden answer from S-DEMO, a clarifying question, or an out-of-scope redirect).

4.2 Farmer voice: 30 notes + 5 controls

  • Categories: Roman Urdu/spoken Urdu 14, Punjabi-accented Urdu 8, mixed EN/Urdu 5, ambiguous 3. Twelve are spoken versions of text items (paired subset: measures the voice-vs-text gap directly).
  • Recording matrix: ≥ 6 speakers (mixed age/gender), ≥ 3 phones (low-end Android, mid Android, iPhone), conditions 12 quiet / 10 indoor noise (fan, TV) / 8 outdoor (street, tractor or market sound), 3–45 s, recorded inside WhatsApp and pulled through our real webhook and media path.
  • Controls (not scored in the 30): 2 silent notes, 1 music clip, 1 Pashto or Sindhi note, 1 note over 120 s. Expected: graceful message, zero invented requests.

4.3 Multi-turn and commands: 30

  • 20 follow-up turns: "aur tamatar?" (crop switch keeps place and quantity), "Lahore ka?" (place switch), "2 number wali ki tafseel" (reference), "agle hafte?" (horizon), "nahi, 80 mann" (correction).
  • 10 alert commands: subscribe, threshold up/down, list, STOP.

4.4 Procedure

  1. Run every STT candidate on all voice items → score A.
  2. Feed gold transcripts and each STT output to each parser option (P0, P1; P2 if approved) → separates STT errors from parser errors.
  3. Run the full pipeline end to end for the best STT × parser combination → score B–E.
  4. Repeat LLM runs 3 times; report mean and worst run.
  5. Reply quality (language mirroring, clarity of the range, honesty) is a 1–5 rubric by 2 raters on 20 sampled replies. WER/CER is reported but not gating.

Decision rule. The LLM is the primary parser only if it beats the rule-based parser by ≥ 5 points on text critical-slot match and passes C. Otherwise the rule-based parser is primary and the LLM handles only messages the rules cannot parse. No silent model swap: any change is a recorded decision. An STT option failing A cannot be primary; if none passes A, echo-confirm becomes always-on for voice (one extra tap, demo stays correct).

6. Voice failure strategy (runtime)

  1. Pre-checks before any STT call: duration < 1 s → "dobara bhejein"; > 120 s → transcribe the first 120 s and say so; energy/silence check → silent notes never reach an STT (prevents the Gemini invention seen in the Manzil test).
  2. STT chain: primary → (error / timeout 6 s / empty / garbage) → fallback → (still failing) → "Awaaz samajh nahi aayi, likh kar bhej dein" + alert log.
  3. Transcript sanity checks: empty, implausible words per second, repeated-token loops, script outside {Latin, Urdu-Arabic, Devanagari}.
  4. Critical-slot echo: if crop, place or quantity came from voice and the resolver was not exact, or a number fails the plausibility band (e.g. 5,000 mann from a smallholder), echo before answering: "Aapne kaha: pyaz, Okara, 50 mann. Sahi? [Haan] [Badlein]".
  5. Non-agricultural audio (music, chatter): no tool call, polite clarification. Unsupported language: ask to speak Urdu or type.
  6. Audio is deleted after transcription for farmer messages; benchmark recordings are team-owned and kept.

7. D9: Language understanding and orchestration → DECIDED

  • Pattern: a single code-controlled workflow, not multi-agent and no agent framework. Per message: deterministic pre-processing (dedupe, consent gate, STT) → rule-based parse → if incomplete or messy, one LLM turn with intent-scoped tools (≤ 3 iterations) → deterministic renderer.
  • Tools (strict schemas, all deterministic): resolve_crop, resolve_place, update_query (slot patch with raw spans), price_now, get_forecast, best_mandis, get_outlook, subscribe / set_alert / stop.
  • The LLM passes raw spans ("dedh sau mann", "Okara") and picks among resolver candidates; it never emits a mandi ID, a crop ID or a number of its own.
  • Models: FYP-I = rule-based + Gemini free tier on team phones only. FYP-II user test = rule-based + a paid no-training LLM if the supervisor approves ≈ $10–15; otherwise rule-based only for real farmers. Same prompts and tools for any model (one adapter).
  • Scope guard (Meta §4.7): anything outside prices, mandis, outlooks and alerts gets a fixed redirect.

8. D10: STT → DECIDED (subject to benchmark A)

  • Primary: ElevenLabs Scribe v2 with keyterms from the crop and place gazetteers. Fallback: faster-whisper on the VM if its latency fits E, else Gemini audio behind the silence check.
  • Normalised text = the STT's native output (Urdu script, Roman or mixed) passed straight to the parser; the gazetteers hold Urdu-script and voice-STT aliases (no transliteration step, as Manzil D18).
