1. Real issues (36)

Farmer input

R-01

FailureRapid bursts get outdated replies: "pyaz" → (2 s) "Lahore" → (3 s) "50 mann".
WhyCoalescing merges only messages already pending when the job is claimed; message 1 starts a turn at once.
ImpactThree contradictory replies; wasted LLM quota (free tier is small).
SeverityP1
Mitigation(a) 1.5 s quiet-window debounce for text, capped at 4 s. (b) Supersede check: before sending, if a newer inbound exists, discard the draft and re-run once with all messages.

A. Critical blockers: must be designed in before coding

These change core flows, the schema or the evaluation protocol, so they are cheap now and expensive later.

  1. R-06 + R-05: Template-rendered facts and the closed-intent unknown path. Changes C5's prompt contract and C11 from Day 1.
  2. R-07: Coverage gate in the batch writer and the forecast reader. Changes C9/C13 and the forecast table.
  3. R-13 + R-14: reported_at in the schema, leakage tests in CI, lockbox sealed with a hash before any model runs. Changes the loader and the repo layout.
  4. R-11: P10 risk rule inside the F2 engine, not added later. Changes C10's output payload.
  5. R-01 / R-02: Turn assembly: debounce, supersede-before-send, STT inside the turn. Changes C2/C3 job semantics.
  6. R-10: Unit tests per loader with a known row before any data is used.
  7. R-34: Source SYN in the schema and the "Demo data (synthetic)" label in the renderer and chart helpers from Day 1; results framed as pipeline verification.
  8. R-23: The real-user mode flag (paid no-training LLM or rule-only) exists before the fresh-SIM number goes live.

E. Architecture changes NOT required (the design held)

  • Text + voice convergence after STT; only ordering needed tightening (R-02).
  • Precomputed forecasts read by the bot ("one engine, two uses"): the right boundary for both correctness and evaluation honesty.
  • Postgres job queue and idempotency model.
  • Gazetteer-based resolution with candidates for the LLM; only echoing was strengthened.
  • Single-agent LLM workflow with deterministic tools; no agent framework needed.
  • Single tenant, one VM.
  • Added work: roughly 3–4 person-days inside the existing FYP-I plan, mostly in C9, C10, C11 and C16.
