2. Recommended reply formats (D12)

Rule (from the Manzil red team, R-21): every fact is rendered by a deterministic template from the tool payload. The LLM may add one short framing sentence and a question back; it may not restate any number.

2.1 Price now

[LLM wrapper, optional] Ji, ye Lahore ka taaza rate hai:
[template] 🧅 Pyaz · Lahore (Badami Bagh)
Rs 2,850–3,000 fi mann (40 kg) · 10 Dec · AMIS Punjab
[buttons] [Agle din ka andaza] [Kahan bechoon?] [Alert lagayein]

If the latest quote is older than 2 trading days, the template adds "⚠ Taaza rate nahi mila; aakhri rate 7 Dec ka hai".

2.2 Short-term forecast (F1)

[template] 🍅 Tamatar · Lahore · agle 3 din ka andaza
Rs 2,100–2,600 fi mann (80% andaza) · beech ka andaza Rs 2,350
Wajah: mandi mein aamad zyada hai · baarish ke baad supply barhi
[template] Ye andaza hai, waada nahi.
[buttons] [Kahan bechoon?] [Alert lagayein] [Doosri mandi]

2.3 Where to sell (F2)

[echo] Pyaz · 50 mann · Okara se
[template] 1. Lahore: Rs 3,050–3,250 fi mann · kharche ke baad ≈ Rs 1,47,000
2. Okara: Rs 2,850–3,000 · ≈ Rs 1,44,500
3. Sahiwal: Rs 2,900–3,100 · ≈ Rs 1,43,800
Lahore nazdeeki mandi se ≈ Rs 2,500 zyada deti hai, transport ke baad bhi.
Kharche: transport Rs 85/mann (130 km), commission 6%  ← farmer can challenge these
[buttons] [1 ki tafseel] [Transport badlein] [Alert lagayein]

When the risk rule fails: "Nazdeeki mandi (Okara) theek hai: door jaane ka faida yaqeeni nahi." Numbers above are illustrative, not model output.

2.4 Harvest outlook (F3)

[template] 🍅 Tamatar · Lahore · February 2027 ka andaza
Rs 1,900–3,400 fi mann · aam se zyada hone ka imkaan 70%
Wajah: pichle season rate kam tha, is liye kam kashtkaron ne lagaya.
⚠ Ye door ka andaza hai, faasla bara hai. Faisla apni samajh se karein.

Where F3 has no skill for the crop: "February mein tamatar ka aam rate Rs X–Y raha hai. Is fasal ke liye hamara model aam rate se behtar andaza nahi deta."

2.5 Clarifications and errors

  • Missing crop: list message (covered crops). Missing place: location request message + "ya shehar ka naam likhein". Ambiguous place: ≤ 3 buttons with canonical names.
  • "Bori" without weight: buttons [50 kg] [100 kg] [Doosra].
  • Out of coverage: "Abhi sirf Punjab ki mandiyan aur pyaz, tamatar, aloo, gandum." Out of scope: fixed redirect (Meta §4.7 scope guard).
  • Uncovered series: "Is mandi ke liye andaza dene ke liye data kaafi nahi; taaza rate ye hai…"

4. Conversation-state model (D13, minimum persistent state)

All in Postgres, keyed by the farmer's hashed number. Text and voice write the same records; modality is only a source attribute.

RecordFields (minimum)Purpose
wa_useruser_id, wa_number_enc, wa_number_hash, preferred_language, consent_at, district (approx.), last_inbound_at, service_window_expires_atIdentity, consent, window rule
query_state (1 per user)intent, crop, place {mandi_ids[], origin lat/lng, status RESOLVED / AMBIGUOUS / UNKNOWN / OUT_OF_COVERAGE}, quantity_kg, unit_raw, horizon; each slot with raw, source (text/voice/pin/inferred), confidence, confirmed, updated_atCurrent question; voice-sourced slots visible for echo logic
query_patch_logversion, patch[], message_idUndo ("pehle wala"), debugging, benchmark
answer_shownanswer_id, kind (PRICE / F1 / F2 / F3), run_id, positions [1…n → mandi_id], reply_wamid, shown_atResolves "2 number wali" and quoted replies; proves which run produced the numbers
pending_clarificationslot, candidates[], asked_wamid, expires_atHolds the open question; no tool call that needs the slot while open
subscriptionuser_id, type, crop_id, mandi_id, direction, threshold, armed, last_sent_at, activeAlerts and digests
message_logwamid, direction, modality, text_or_transcript, stt_meta, intent, tool_calls_json, tool_payload_json, validator_resultAudit, replay, live evaluation

What the LLM sees per turn (compact): query_state summary, the last answer's positions (position → mandi name + one-line facts), pending_clarification, the last ~6 messages, the language preference. Never the full history; never phone numbers.

5. Key edge cases

  1. Answer from an old run: "2 number wali" asked next morning → re-fetch from the new run; if the ranking changed, say so ("aaj ki taaza ranking ye hai").
  2. Quoted reply to an old answer: context.id → reply_wamid → positions; honoured, but numbers are re-fetched.
  3. Two crops in one message ("pyaz aur aloo ka rate"): two answer blocks in one reply, each from its own tool call.
  4. Pending clarification ignored: keep it, process the new slots, re-ask once, expire after 2 turns.
  5. Voice then text in a burst: processed in WhatsApp-timestamp order inside one serialised turn (file 08).
  6. Quantity implausible ("5,000 mann" from voice): echo-confirm before F2.
  7. Pin far from all covered mandis (> 150 km): OUT_OF_COVERAGE with the nearest covered mandi named.

6. Decisions

D12 → DECIDED. Text answers with template-rendered fact blocks + up to 3 reply buttons; list messages for pickers; native location messages on request; no carousels, no images, no voice replies in FYP-I.

D13 → DECIDED. DB-persisted structured query state with per-slot provenance, op-based patches, answer positions with run IDs, pending clarification; compact snapshot to the LLM; positions valid 24 h for the latest answer; state reset after 30 days.

D14 → DECIDED. Explicit opt-in; threshold alerts and daily digests evaluated after the daily run; templates outside the window; hysteresis and daily caps; template budget cap; STOP deletes.
